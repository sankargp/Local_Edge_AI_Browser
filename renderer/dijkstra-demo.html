Dijkstra's algorithm: finding the cheapest route through a graph

Dijkstra's algorithm solves the single-source shortest-path problem for graphs whose edge weights are never negative. It is one of the clearest examples of a greedy algorithm that is both practical and provably correct.

The problem it solves

A graph represents a collection of things and the connections between them. A road network is the familiar example: intersections are vertices, roads are edges, and the length or travel time of each road is its weight. Given one starting vertex, the goal is to calculate the smallest total weight needed to reach every other vertex. The same abstraction appears in packet routing, dependency analysis, game navigation, logistics, and many recommendation systems.

“Shortest” does not have to mean physically short. An edge might represent money, risk, latency, energy use, or the number of transfers. What matters is that all edge weights are zero or positive. That restriction is not a minor implementation detail; it is the reason the algorithm can safely commit to a route once it has chosen it.

The core insight

The algorithm maintains a best-known tentative distance for each vertex. At the beginning, the source has distance zero and every other vertex has infinity. It repeatedly chooses the unvisited vertex with the smallest tentative distance, declares that distance final, and then tries to improve the estimates of its neighbors. Trying to improve a neighbor is called relaxing an edge: if reaching a neighbor through the newly finalized vertex is cheaper than the old estimate, replace the old estimate.

The greedy choice is safe because a path that reaches the selected vertex later must travel through vertices whose tentative distances are at least as large. With non-negative edges, adding more edges can never make that later route cheaper. Thus no unvisited route can invalidate the distance just finalized.

A small worked example

Suppose A connects to B with cost 4 and C with cost 1. C connects to B with cost 2 and D with cost 5. B connects to D with cost 1. Starting at A, the tentative distances are A = 0, B = 4, C = 1, and D = ∞.

C is chosen first because 1 is the smallest unresolved distance. Relaxing C→B changes B from 4 to 3, and relaxing C→D changes D from ∞ to 6. B is now chosen at distance 3; its edge to D improves D from 6 to 4. The final shortest paths are A→C at 1, A→C→B at 3, and A→C→B→D at 4.

Data structures and pseudocode

A simple implementation scans every unvisited vertex to find the smallest tentative distance. That is easy to teach but costs O(V²), where V is the number of vertices. For sparse graphs, a min-priority queue is far more efficient. The queue stores candidate pairs of distance and vertex, allowing the next most promising vertex to be removed in logarithmic time. Since a vertex's estimate may improve several times, many implementations insert a new queue entry and discard stale entries when they are later popped.

dist[source] = 0
dist[all other vertices] = infinity
push (0, source) into minPriorityQueue

while queue is not empty:
    (currentDistance, u) = pop smallest entry
    if currentDistance != dist[u]:
        continue  // stale queue entry

    for each edge (u, v, weight):
        candidate = dist[u] + weight
        if candidate < dist[v]:
            dist[v] = candidate
            previous[v] = u
            push (candidate, v) into queue

With an adjacency list and binary heap, the usual running time is O((V + E) log V), where E is the number of edges. The `previous` array is optional for distance calculation but essential when an application needs the route itself. Starting at the destination and following `previous` pointers backward reconstructs the path.

Why negative edges break the proof

Imagine that the algorithm finalizes a vertex at distance 5, then later discovers a route that first travels to a vertex at distance 10 and takes a negative edge of weight −8 back to the finalized vertex. The newly discovered route costs 2, contradicting the finalization. Because that possibility exists, Dijkstra's algorithm must not be used with negative edge weights. Bellman–Ford is a standard alternative when negative edges are allowed and can additionally detect reachable negative cycles.

Engineering considerations

Real systems must decide what a vertex and weight mean before choosing an algorithm. GPS routing often uses travel time, but time depends on traffic and turn restrictions, so the graph may need to encode direction, time, and state. Large applications may terminate as soon as one target is finalized rather than computing routes to every vertex. Bidirectional search can help for a known source and destination, while A* adds a heuristic estimate to direct the search toward a goal.

Correctness also depends on numerical choices. Distances can overflow fixed-width integer types, floating-point values can accumulate rounding error, and a disconnected vertex should remain at infinity. A priority queue improves speed but does not change the algorithm's meaning: the invariant remains that every finalized distance is the cost of a cheapest path from the source.

Takeaway

Dijkstra's algorithm is powerful because its idea is compact: always expand the cheapest unresolved route, then update what that route makes possible. The non-negative-weight condition turns that local decision into a globally correct one. Once the graph, weight semantics, and data structures are chosen carefully, it scales from a classroom map to substantial routing systems.
